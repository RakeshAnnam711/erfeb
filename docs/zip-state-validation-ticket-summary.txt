Google Autocomplete ZIP Validation Ticket Summary

Ticket issue
------------
Checkout was allowing users to continue when the selected shipping address and ZIP code no longer matched.

Example:
- User selects a Google address suggestion for New York.
- Google fills the ZIP code as 10001.
- User manually changes the ZIP code to 94105.
- Checkout should not allow the user to continue to payment.


Current approach
----------------
Production storefront is using Google Places autocomplete for address suggestions.

Even though Smarty preferences exist in Business Manager, live checkout suggestions show "powered by Google", and the frontend integration config does not expose Smarty values. Because of that, this fix uses the Google autocomplete selection that is already active on the storefront.


What was changed
----------------
1. Store the state/country returned by Google autocomplete.

File path:
autobahn/rvw_autobahn_core/cartridges/rvw_autobahn_core/cartridge/client/default/js/thirdParty/googleAutoComplete.js

When a shopper selects a Google address suggestion, the code already fills the checkout address fields.

Now it also stores these Google-selected values on the shipping form:
- data-google-selected-state
- data-google-selected-zip
- data-google-selected-country


2. Block payment if Google cannot confirm the entered ZIP belongs to the selected state.

File path:
autobahn/autobahn_client_core/cartridges/autobahn_client_core/cartridge/client/default/js/checkout/plugin/members.js

Before checkout moves from Shipping to Payment, the code checks the current US shipping state and ZIP.

If a Google-selected state is available, it uses that as the expected state. If the page was refreshed and the Google-selected state is no longer available, it uses the currently selected State dropdown value.

It checks:
- Google-selected state or current selected state
- Currently selected state
- The currently entered ZIP code

Checkout first requires the entered ZIP to be a 5-digit US ZIP. Then it asks Google Geocoder to confirm that the ZIP exists and belongs to the Google-selected state.

If the selected state does not match the Google-selected state, or Google cannot confirm the entered ZIP belongs to that state, checkout stays on Shipping and shows this error below the ZIP field:

The ZIP code entered does not match the selected City and State. Please correct the shipping address to continue.


3. Saved address dropdown is excluded from Google validation.

File path:
autobahn/rvw_autobahn_core/cartridges/rvw_autobahn_core/cartridge/client/default/js/checkout/shipping.js

When a shopper chooses a saved address from the address dropdown, the code clears the stored Google-selected ZIP/state.

Reason:
Saved addresses do not come from a fresh Google autocomplete selection, so they should not be validated against a previous Google-selected address.


Important limitation
--------------------
This fix validates the path where the shopper selects an address from Google autocomplete and then edits the ZIP/state afterward. It also validates the current US state/ZIP after refresh, because the Google-selected marker may be lost but the form values remain.

It does not fully validate:
- A manually typed address where the shopper never selects a Google suggestion.
- A saved address selected from the saved address dropdown.
- Whether the ZIP is correct for the exact street address.

Those paths would require a real address validation API call on submit, such as Smarty Street Address validation, Google Address Validation API, or another backend validation service.

This fix validates state/ZIP compatibility using Google when available. For example, a New York Google-selected address with New York selected as the state and a valid New York ZIP can continue, while a New York Google-selected address with an invalid ZIP like 00000/10100 or a California, Maryland, or New Hampshire ZIP is blocked.


Expected QA behavior
--------------------
Scenario 1: Google-selected address, unchanged ZIP/state
- Select a valid Google suggestion.
- Leave ZIP/state as Google filled them.
- Continue to Payment should work.

Scenario 2: Google-selected address, changed ZIP to valid same-state ZIP
- Select a valid Google suggestion for New York.
- Change ZIP to another valid New York ZIP.
- Continue to Payment should work.

Scenario 3: Google-selected address, changed ZIP to invalid ZIP
- Select a valid Google suggestion for New York.
- Change ZIP to 00000 or 10100.
- Continue to Payment should be blocked.
- ZIP field should show the mismatch error.

Scenario 4: Google-selected address, changed ZIP to different-state ZIP
- Select a valid Google suggestion for New York.
- Change ZIP to a California ZIP like 94105.
- Continue to Payment should be blocked.
- ZIP field should show the mismatch error.

Scenario 5: Refresh after wrong ZIP
- Select a Google address.
- Change ZIP to a different-state or invalid ZIP.
- Refresh the page.
- Click Continue to Payment.
- Checkout should still be blocked.

Scenario 6: Saved address dropdown
- Select a saved address.
- The current US state/ZIP compatibility check can still run, but saved addresses are not validated against a previous Google-selected address.


Plain English summary
---------------------
We are using the Google address suggestion the shopper selected as the trusted state for this specific flow.

If the shopper selects a Google address and then changes the state or ZIP before payment, checkout checks whether the selected state matches the Google-selected state and whether Google can confirm the entered ZIP belongs to that state.

If the ZIP belongs to a different state, checkout blocks payment and shows the ZIP error.
